## Spring Batch

### 배치란
- 일정 시간 동안 대량의 데이터를 한 번에 처리하는 방식이다.
- Spring Batch라는 프레임워크를 사용해야하는 이유는?
    - 아주 많은 데이터를 처리하는 중간에 프로그램이 멈출 수 있는 상황이 있기 때문이다.
    - 10만개의 데이터를 복잡한 JOIN을 걸어 DB간 이동시키는 도중 프로그램이 멈춰버리면 처음부터 다시 시작할 수 없기 때문에 작업 지점을 기록해야한다.
        - 이러한 정보를 기록하는 '메타 테이블 DB'를 가지고 있기도 하다.
        - 실제 데이터는 '운영 테이블 DB'에 있다.
    - 급여나 은행 이자 시스템의 경우 특정 일에 했던 처리를 또 하는 중복 불상사도 막아야 한다.

### Spring Batch 동작 방식
- '배치'는 데이터를 효율적으로 빠르게 처리하는 것도 중요하지만, 아래의 사항이 중요하다.
    - 내가 하고 있는 작업을 어디까지 했는지 계속해서 파악
    - 이미 했던 일을 중복해서 하지 않게 파악 (배치는 보통 주기적으로 스케쥴러에 잡혀 실행되기 때문이다.)
- 한 번에 많은 양을 읽으면 메모리에 올리지 못하거나 실패 위험 및 속도적인 문제가 커진다. 따라서, 끊어서 읽는다.
- 이러한 동작을 기록하는 테이블을 "메타 데이터"라 한다.

### 배치 활용 예시
- 은행 이자 시스템
    - 매일 자정, 전일 데이터를 기반으로 이자를 계산해서 이자 지급을 수행한다.
    - 10분이라는 빠른 시간 동안 처리 후 은행 영업에 차질이 없도록 만들어야 한다.
- 주기별 회원 권한 조정
- 급여
- 주기별 보고서
- 데이터 삭제

### Spring Batch 내부 구조도
![img.png](img.png)
- JobLauncher
    - 하나의 배치 작업(Job)을 실행시키는 시작점이다.
    - 컨트롤러와 연결하여 배치 작업을 실행하거나 스케쥴러를 통해 주기적으로 실행할 수 있다.
- Job
    - '읽기 - 처리 - 쓰기' 과정을 정의한 배치 작업이다.
- Step
    - 실제 하나의 읽기, 쓰기, 처리 작업을 정의한 부분으로, 1개의 job에서 여러 과정을 진행할 수 있기 때문에 1:N의 구조를 가진다.
        - ItemReader
        - ItemProcessor
        - ItemWriter
- JobRepository
    - 메타테이블에 작업의 실 행흐름을 저장한다.
